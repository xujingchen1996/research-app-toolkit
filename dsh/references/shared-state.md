# RA 共享档案契约

## 工作区与资源边界

- 档案路径固定为当前会话工作区 `{{cwd}}/.ra/memory.md`。`{{cwd}}` 在参考文件中是说明占位符，实际使用会话工作目录，不把它当作字面目录名。
- 本参考文件与技能的相对路径以所加载技能返回的 `resourceBase` 为准，不以 shell 工作目录为准。
- 九个技能共享同一个工作区档案；不同工作区互相隔离。不读取或修改 Codex 的全局记忆与插件缓存。
- 档案缺失时，从本文件相对路径 `../templates/memory.md` 读取模板，并用当前环境的文件工具创建 `.ra/memory.md`。已存在时读取并保留用户数据，不覆盖为模板；只读权限下给出草稿并说明无法写回。
- 所有模板及技能安装文件只读；可写输出保存在工作区 `.ra/outputs/`，保留源文件。

## 档案更新

保留 YAML frontmatter 字段与固定英文章节标题，内容可中文/英文。完整重组当前档案，不只在末尾追加；保留已有 CV、偏好及其他技能的信息，不得凭空填充。只在用户任务需要建立/更新申请档案或用户明确要求时写回，不记录无关对话。多任务同时操作时避免并发写同一档案。

`cv_profile_analyzed` 只有在 CV 已读取并完成基本提取后才设为 true；内容缺失时说明缺口，不把 false 当成所有任务的强制阻塞。材料已足够时可以直接继续。

## 语言与证据

当前请求 > 档案 `preferred_language` > 当前对话/目标项目常用语言。允许 zh、en、bilingual；英文专业名称和档案结构保持稳定。

学校、奖学金、截止日期、导师招生与近期研究必须用当前联网信息核验，优先官网与原论文。结果附来源、核验日期和具体适用周期；无法核验写待核实。引用不能凭空生成。

## 环境能力

- 用 DSH 的 `skill` 工具加载技能；不调用不存在的 Codex API。用户也可用 `/技能名` 显式调用。
- 用现有文件工具及 shell 提取用户材料；不自行安装依赖或改宿主权限来完成普通任务。
- 可选生命科学技能、Zotero 与图像生成只有在当前目录/工具中确实存在才使用；否则用论文文件、已有联网工具及图像提示词继续。
- 默认不委派；用户明确要求且宿主具有相应工具才并行。
- 本包撰写邮件及申请材料不代表发送、提交、签署或录取承诺。用户要求正式操作时再检查相应工具和授权。

## 四个工作台标签页

UI 与模型共用 `.ra/memory.md` 和 `.ra/workbench.json`。处理来自界面的请求时先调用 `ra_workbench`，action 为 read，获取最新状态与 revision。档案保存使用 profile（markdown、profileRevision 对应的 revision）；记录保存使用 upsert（kind、record、revision）。payload 是 JSON 字符串。

kind 为 schools、professors、documents、interviews。记录字段为 id、title、type、target、status、deadline、source、checkedAt、notes、content；保留原 id 与未知/其他字段，不编造来源或核验日期。工作台结果写入 content，完成时更新 status。过期 revision 会拒绝保存，需要重新读取并合并，不覆盖其他任务结果。

以 `ra_workbench` 更新数据，避免工具与 UI 并发覆盖。用户只要当前对话回答时，不强制创建记录。旧 Agent 尚未加载新增工具时，先提示新建 RA 会话；不能伪装工具已存在。UI “准备任务”仅填写输入框，用户发送后才执行，不能把记录创建视为对外发送/提交授权。
